# Golden vectors

Everything here except `offload/` is a **verbatim copy** of voidbind-go's
`testvectors/vectors/` (its `testvectors` package, the single source of truth)
at the commit in [`VOIDBIND_GO_REF`](VOIDBIND_GO_REF). CI (`vector-drift` in
`.github/workflows/test.yml`, running `scripts/check-vector-drift.sh`) fails if
they differ. To update: re-copy the files from voidbind-go at a newer commit and
bump `VOIDBIND_GO_REF` in the same change — never hand-edit a vector here.
`offload/` comes from heyarr-core and is not checked.

## `device-scheme-vector.json`

The **Device authorization-scheme** vector: an enrolment cert, a possession proof,
the joined `<cert>~<proof>` credential and the full `Authorization` header, all
minted by the **real Go code** — voidbind-go v0.5.0 `enrolment.SignCert` /
`SignPossession` (what heyarr-core vendors) — with fixed seeds and clocks:

- user seed `00..1f`, device seed `80..9f` (Ed25519 is deterministic);
- cert `iat` 1788307200 / `exp` 1796083200;
- possession `now` 1788350400, default 120 s ttl.

First generated by a scratch Go test during the heyarr-mobile Device-scheme work on
2026-09-02; voidbind-go now commits the generator (`enrolment.TestDeviceSchemeVector`,
which reproduces this file byte-for-byte and replays it), and it is carried here so `DeviceSchemeVectorTest`
proves the library's `PossessionProof` / `DeviceCredential` bytes are exactly what
`enrolment.VerifyPossession` accepts. The same values are inlined in
`commonTest/.../auth/PossessionProofTest.kt` (vector B) so every target runs them.

If a value in this file ever has to change to make a test pass, the wire format
broke — stop and investigate against voidbind-go.

## `typ/` and `membership/typed-*`

These are the token-type (`typ`) vectors from voidbind-go ADR-0009, copied
verbatim from voidbind-go `testvectors/vectors/` at `VOIDBIND_GO_REF`. See
`typ/README.md` for the schema.

`TypVectorTest` replays the checks this library can answer
(`op`/`op_user`/`possession`) at their phase-1 verdicts. It also asserts that
`Cert.parse` refuses every token Go's cert verifier calls `wrong_type`, and that
the typed mint paths reproduce Go's typed tokens byte for byte.
`MembershipVectorTest` picks up the `typed-*` membership cases on its own. They
include a typed cosigned remove, which fails if `coreBytes` drops `typ`.
